# Рецензия БЯМ на лабораторную работу № 6

## 1. Вердикт по работе
**Вердикт:** готова.

**Обоснование вердикта:**
Комплект артефактов ЛР 6 представлен в полном объеме согласно спецификации: `lab6_report.md`, `service_tests.log`, `registry.json`, `monitoring_log.txt`, `monitoring_status.png`. В отчете отражены ключевые эндпоинты (`/health`, `/predict`, `/models`, `/promote`, `/rollback`, `/metrics`), схемы Pydantic и результаты нагрузочного дрилла. Все негативные контроли сработали: невалидные запросы отклоняются кодом 422 с описанием ошибки, подмена хеша весов модели при инициализации реестра блокируется исключением `ValueError: SHA256 mismatch`, а бесшовное переключение версий (`v1.0.0-ml` -> `v2.0.0-dl` -> `v1.0.0-ml`) выполнено с 0 потерянных запросов при 100.000 % успешных ответов (2156 из 2156), что превосходит норматив в 99.9 %.

**Список замечаний:**
1. В `service_tests.log` зафиксировано предупреждение `StarletteDeprecationWarning: Using httpx with starlette.testclient is deprecated; install httpx2 instead`. На прохождение тестов предупреждение не повлияло (7 passed), однако требует фиксации версий зависимостей.
2. В `lab6_report.md` в таблице дрилла указано фиксированное число запросов (2156), однако не приведена детальная гистограмма распределения задержек по квантилям (p50, p90, p99), приведены только общие показатели сервиса мониторинга (p95 = 0.62 мс).

## 2. Противоречия и невоспроизводимые числа
Противоречий между файлами не обнаружено:

## 3. Сильные стороны
1. Строгая валидация контракта Pydantic: корректная обработка граничных условий (длина строго 57 признаков, неотрицательность значений) с возвратом статуса 422.
2. Потокобезопасная реализация реестра моделей с использованием `threading.Lock`, гарантирующая zero-downtime и отсутствие race conditions при смене активного указателя.
3. Полный негативный контроль целостности: автоматический расчет и верификация контрольных сумм SHA-256 перед загрузкой весов модели в память.
4. Выделенный сервис мониторинга со сбором телеметрии (задержка p95, память RSS) и графической фиксацией динамики в `monitoring_status.png`.
