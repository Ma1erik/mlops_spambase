# Критический комментарий обучающегося к рецензии БЯМ

**Лабораторная работа:** №3 (Пайплайн DL-модели: полный датасет и чанки)
**Обучающийся:** Скоробогатов И. В.
**Вариант:** №45 (Spambase)

| Пункт рецензии БЯМ | Позиция | Обоснование позиции |
| :--- | :--- | :--- |
| **1. Соответствие архитектуры MLP (57 -> 64 -> 32 -> 1)** | Согласен | Архитектура полностью повторяет карточку варианта P1 (табличный бинарный классификатор), слои Dropout предотвращают оверфиттинг. |
| **2. Изоляция масштабирования («чистый Train»)** | Согласен | Использование `partial_fit` для `StandardScaler` в потоковом режиме гарантирует расчёт статистик исключительно по обучающим чанкам без утечки теста. |
| **3. Оценка эффективности памяти стриминга (сокращение в 36 раз)** | Согласен | Падение пика RAM с 80.83 МБ до 2.22 МБ подтверждено `tracemalloc` и воспроизводится тестом негативного контроля `test_streaming_memory_bounded`. |
| **4. Воспроизводимость и допуск детерминированности** | Согласен | Дельта метрики 0.000000 укладывается в объявленный допуск регламента (<= 0.005), на CPU детерминированные флаги PyTorch отработали корректно. |
| **5. Полнота негативных контролей (4 сценария)** | Согласен | Все сценарии проверены через pytest и залогированы в `controls_test.log`. |
| **6. Рекомендация: вынос Early Stopping на валидационный сплит** | Согласен частично | В учебном контуре остановка по train loss предотвратила data leakage в соответствии с принципом «чистого train». Для промышленного продакшна выделение отдельного validation split обязательно. |
| **7. Рекомендация: динамическое квантование PyTorch** | Согласен | При инференсе на CPU квантование весов до int8 действительно снизит латентность отклика и будет реализовано при сборке сервиса в ЛР 6–7. |
